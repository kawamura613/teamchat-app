# PR を 1 本出す

出すのは **PR 1 本**だけ。アプリのコードは直さない（テストが赤いときは PR を作らずに戻る）。

順番に意味がある。**本文より先にテストを回す**のは、赤なら出さないという判断が先に来るから。**本文より先に AC を判定する**のは、画面を見ないと判定できない AC が 1 つでも残ると、見に行くぶん本文を書き直すことになるから。**push を最後に置く**のは、`git push` が `.claude/settings.json` で `ask` になっていて人の手で止まるから。止まる時点で本文まで出来ていれば、人は中身を確かめるだけで済む。

## 0. 出せる状態か確かめる

| 見るもの | 確かめ方 | 出せないときどうするか |
|:--|:--|:--|
| ブランチ | `git branch --show-current` | `main` なら出せない。`plan-issue-from-design` でブランチを切るところから |
| 対象のイシュー | 引数の番号。無ければブランチ名から取る（`feature/1-auth` → #1） | `chore/` は紐づくイシューが無い。`Closes` を書かない型（手順 4）にする |
| 開いている PR | `gh pr list --head <ブランチ>` | 既にあれば**新しく作らない**。コミットを足して push し、その PR の URL を報告する |
| 範囲 | `git log --oneline main..HEAD` と `git diff main...HEAD --stat` | 0 件なら出すものが無い。何を出すつもりかを聞く |
| 未コミットの変更 | `git status --short` | 手順 1 でコミットする |

## 1. コミットを整える

- 残っている変更は**作業の単位で**コミットする。1 本にまとめない。あとから「どの決めがどのコードになったか」を追えるようにするため（PR #8 は 7 本）。
- **設計書（`docs/design/`）を直すなら、コードより先にコミットする。**「食い違ったらコードではなく設計書を先に直す」という決めが、履歴の順番にそのまま残る。
- メッセージは日本語。1 行目は「〇〇を〜した」＋末尾に ` (#N)`。`chore/` は番号が無いので付けない。
- 1 行目だけで足りないときは本文を足す（何が起きていたか → どのファイルをどう直したか → テストの件数）。直近のコミットが見本になる。
- 末尾の `Co-Authored-By` 行は、セッションの指示で指定された形をそのまま付ける（モデル名はセッションごとに違う）。
- **コミット直前にもう一度 `git status` を見る。**`Edit` / `Write` のあとはフックが Pint を回すので、整形ぶんの差分が後から出ることがある。

## 2. テストを回して出力を取る

```bash
./vendor/bin/sail artisan test 2>&1 | tee <scratchpad>/test.txt
```

- コンテナが落ちていたら `sail up -d`。DB が古ければ `sail artisan migrate`。
- **1 件でも赤なら PR を出さない。**直して回し直す（`CLAUDE.md`「テストが落ちた状態で作業を終えない」）。直せない理由があるなら、PR を作らずに人へ伝える。
- 本文に貼るのは `test.txt` の中身**そのまま**。打ち直さない・件数や秒数を手で書き換えない。長すぎて省くときは、**省いたと書く**。

## 3. 受け入れ条件を判定する

- `acceptance.md` の **1 章の対応表**で、イシューが 7 つの実装単位のどれかを決める。イシューの F 番号ではなく**単位の番号**で引く。
- **2 章から `AC-<単位>-◯` を一字一句写す。**言い換え・要約・足し引きをしない。写し変えると、設計書と PR で受け入れ条件が 2 通りになる。
- 判定は **満たす / 満たさない / 判定できない** の 3 つ。根拠は確かめ方で書き分ける。

| 何で確かめたか | 根拠の欄に書くこと |
|:--|:--|
| テストで示せる | `AuthTest::test_〇〇`（クラス::メソッド） |
| 画面でしか見えない（余白・文言の位置・ログインユーザーごとの見え方） | 「画面で確認」＋**その手順と結果** |
| まだ見ていない | **「判定できない」**と書き、何をすれば判定できるかを添える |

- 画面でしか見えない AC が残ったら、`uat-with-playwright` で見てから書く。**見ずに「満たす」と書かない。**テストが緑でも画面では満たせていないことが実際にあった（AC-1-4 の戻るボタン。応答に `no-store` が無く、履歴から古いページが出ていた）。
- 「満たさない」「判定できない」が 1 つでもあるなら、**PR を作る前に人へ伝えて、出すかどうかを決めてもらう。**

## 4. 本文を組む

本文はファイルに書いて渡す（`<scratchpad>/pr-body.md`）。テスト結果がコードブロックなので、ヒアドキュメントに直接入れるとフェンスの入れ子で壊れる。`--body-file` なら壊れない。

````markdown
## 何をした

単位◯「〇〇」

## テスト結果

```
$ ./vendor/bin/sail artisan test
（出力をそのまま貼る）
```

## 受け入れ条件の判定

| AC番号 | 受け入れ条件 | 判定 | 根拠 |
|:--|:--|:--|:--|
| AC-◯-1 | （acceptance.md から 1 行写す） | 満たす | `ChannelTest::test_〇〇` |
| AC-◯-2 | （同上） | 満たす | 画面で確認（手順と結果） |

## 設計書との差

（`docs/design/` を直したファイルと理由。無ければ「なし」）

Closes #<イシュー番号>
````

- 「何をした」は作ったものだけでなく、**作らなかったものとその行き先の単位**も書く。あとで「なぜ無いのか」を調べ直さずに済む。
- 途中で範囲が変わったなら、その経緯も書く（何を決め直して、どの設計書のどこに反映したか）。
- 末尾の生成物の注記は、セッションの指示で指定された形をそのまま付ける。

`chore/`（イシューに紐づかない直し）のときは 3 か所を変える。

| 節 | どう変えるか |
|:--|:--|
| 何をした | 単位◯ ではなく、**何を直したか**と**なぜイシューにしなかったか** |
| 受け入れ条件の判定 | AC が無いので表を置かず、**確かめ方**（回したテストと見た画面）を書く |
| `Closes` | 書かない |

## 5. push して PR を作る

- `git push -u origin <ブランチ>` は `ask` で止まる。**黙って別の手で回避しない。**止まったら、組んだ本文を見せて確認を取る。
- タイトルはコミット 1 行目と同じ形。**イシューは「〜する」、PR は「〜した」**（例: `社員が自分でアカウントを作ってログインできるようにした (#1)`）。

```bash
gh pr create --base main --title "<タイトル>" --body-file <scratchpad>/pr-body.md
```

- draft にしない。ラベルもレビュアーも付けない（イシューと同じで、この案件では使っていない）。

## 6. 報告する

- PR の URL。
- テストの件数と結果（自分で回した事実として）。
- 「判定できない」が残っている AC があれば、それと次の一手。
- 設計書を直したファイルと理由（無ければ「なし」）。

## 7. マージが済んだら片付ける

マージするかは人が決める。**頼まれてからやる。**

```bash
gh pr merge <番号> --merge --delete-branch   # PR #8 と同じマージコミットの形
git checkout main && git pull
git fetch --prune
git branch -d <使用済みのブランチ>
```

- リモートとローカルの**両方**消す。消え残りは `git branch -vv` の `[gone]` で分かる。
- 公式プラグイン `commit-commands`（Anthropic 製）の `/clean_gone` を入れているなら、`[gone]` の掃除はそれで済む。

## やらないこと

- **テストが赤のまま PR を出さない。**
- **見ていない AC を「満たす」と書かない。**判定できないものは「判定できない」と書く。
- `git push` を黙ってやらない。`ask` は人に見せるための関門。
- 設計書とコードが食い違ったまま出さない。`docs/design/` を先に直し、そのコミットを同じ PR に入れる。
- 既にあるコミットを `rebase` や `squash` で作り直さない。履歴を潰すと、どの決めがどのコードになったかが追えなくなる。
- イシューを手で閉じない（`Closes #N` に任せる）。
- 差分のレビューはしない。頼まれたら `pr-review-against-design`（読み取り専用）に回す。
